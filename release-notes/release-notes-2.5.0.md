# Amazon::API 2.5.0 Release Notes

**Released:** Tue Aug 11 2026

## Overview

Version 2.5.0 is a significant feature and infrastructure release that
introduces Botocore provenance tracking, SHA-256 integrity digests for
service descriptions, Git SHA-based autogeneration metadata in
rendered stubs, and a comprehensive build system overhaul. Several
correctness fixes are also included.

---

## New Features

### Botocore Provenance Tracking

A new provenance subsystem has been added to allow tracking of the
Botocore source data used when generating AWS API stubs:

- **`Amazon::API::Provenance`** — new module for provenance management
- **`Amazon::API::Provenance::Role::KMS`** — new Role for KMS-based provenance
- **`Amazon::API::Provenance::Role::SSM`** — new Role for SSM-based provenance
- **`Amazon::API::BuildInfo`** — new module exposing build-time metadata (e.g. `$GIT_SHA`)
- **`bin/amzn-api-provenance`** — new utility script for provenance management

### Integrity Digests for Service Descriptions

Rendered stubs now include SHA-256 checksums of the Botocore source
files used to generate them, enabling verification and
reproducibility:

- `service_2_digest` — SHA-256 digest of `service-2.json`
- `paginators_1_digest` — SHA-256 digest of `paginators-1.json` (or
  `'no paginators'` if absent)
- Digests are stored in `.api` files and embedded in generated stub
  POD under a new `Botocore` section

### Git SHA in Generated Stubs

Autogeneration timestamps have been **replaced with Git SHAs**
throughout generated output. This makes stub regeneration
deterministic and reproducible:

- `# Autogenerated by version @git_sha@` replaces `# Autogenerated
  @timestamp@`
- POD `AUTHOR` sections now reference the commit SHA rather than a
  wall-clock time
- `Amazon::API::Botocore::Shape::Utils::create_shape` uses
  `@git_hash@` in place of `@timestamp@`

### Botocore Version Tracking

- A `botocore-version.json` file (containing Botocore `version` and
  `commit`) is now generated during builds and embedded in rendered
  stubs
- New `botocore-version` Make target
- Stub POD now includes a `Botocore` section with version, commit, and
  digest information

## Improvements

### `Amazon::API::Botocore`

- **`render_stub`**: reads `botocore-version.json` and injects
  `botocore_version`, `botocore_commit`, `git_sha`,
  `service_2_digest`, and `paginators_1_digest` as template variables
- **`get_service_descriptions`**: calculates SHA-256 digests for
  `service-2.json` and `paginators-1.json`
- **`fetch_boto_services`**: stores `service_2_digest` and
  `paginators_1_digest` in `%BOTO_SERVICES` when metadata is requested
- **`create_stub`**: stores service API files in **deterministic
  order** (`$Storable::canonical = 1`); now persists
  `service_2_digest` and `paginators_1_digest` in `.api` files
- **`module_name`**: refactored to delegate to new private
  `_module_name` helper

### `Amazon::API`

- **`decode_response`**: fixed guard against non-blessed response
  objects — now correctly checks `!blessed $response ||
  !$response->can('content')` and provides a more informative error
  message including `'non-reference'` for scalar arguments

### `Amazon::API::Botocore::Shape`

- **`_init_value`**: fixed early return to use `!defined $value`
  rather than `!$value`, preventing incorrect short-circuit for falsy
  (but defined) values such as `0` or `""`

### `Amazon::API::Botocore::Shape::Utils`

- **`create_shape`**: replaced `@timestamp@` template variable with `@git_hash@`

## Build System Overhaul

This release includes a significant update to the build infrastructure
managed by `CPAN::Maker::Bootstrapper`:

- **`cmb`** replaces `bootstrapper` as the command name for `CPAN::Maker::Bootstrapper`
- **Template variable resolution** via `cmb resolve-vars` replaces
  `sed`-based `@VAR@` substitution for `.pm.in`, `.pl.in`, `.sh.in`,
  and other generated files
- **`gen-vars-file`** Make function added to write template variable
  sidecar `.vars` files for `cmb`
- **`TEMPLATE_VARS`** mechanism introduced; now includes
  `PACKAGE_VERSION`, `MODULE_NAME`, `GIT_SHA`, `GIT_DIRTY`,
  `GIT_EMAIL`, `GIT_USER`, `GIT_NAME`, `PROJECT_NAME`
- **`.includes/local.mk`** added to managed files, enabling
  `cpm`/`carton`-based local dependency installation in `./local`
- **`PERLINCLUDE`** updated to `-I lib -I local/lib/perl5`; syntax
  checking now sets `PERL5LIB=` to isolate the local tree
- **`find-files`** macro now excludes editor backup files (`#*`,
  `.#*`, `*~`, `*.bak`) and sorts results for reproducibility
- **`deps.mk`** generation is now atomic (write to `.tmp`, verify
  non-empty, then rename)
- **`extra-files.mk`** no longer requires `extra-files` to exist before `buildspec.yml`
- **`requires.raw` / `recommends.raw` / `suggests.raw`** scanning now
  operates on `.in` source files
- **`bin/amazon-api.in`** refactored to use the standard modulino
  wrapper pattern
- **`project.mk`**: Botocore pull/state/version recipes restructured
  to avoid unnecessary rebuilds; provenance files cleaned up on
  `clean-local`
- **`git.mk`**: `make repo` target fixed (shell variable quoting,
  `--description` and `create-repo` support, `DRYRUN` support)
- **`DOCKER_CPAN_INSTALLER`** replaces `INSTALLER` for Docker CI builds

## Test Fixes

Four existing tests had package declarations using the `package Name {
... }` block syntax, which is incompatible with older Perl
versions. These have been corrected to use the standard two-statement
form:

- `t/04-rest-xml-payload.t`
- `t/05-rest-xml-nonpayload.t`
- `t/08-rest-xml-header.t`
- `t/09-blob-and-statuscode.t`
